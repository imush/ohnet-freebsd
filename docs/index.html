MinimServer on FreeBSD

How to run MinimServer, the UPnP music server, on FreeBSD or in a TrueNAS CORE jail.

MinimServer is Java, so it runs on FreeBSD, all but ohNet, the native UPnP library it uses. MinimServer ships ohNet only for Linux, Windows and macOS. ohnet-freebsd builds it for FreeBSD as a drop-in replacement for MinimServer's Linux copy. This page also covers FreeBSD's differences from Linux in MinimServer's start and stop scripts.

What you need

  • FreeBSD 13.1 or later, on amd64 (64-bit Intel or AMD). A jail works well, including a TrueNAS CORE jail.
  • Java. The openjdk8-jre package is tested. Newer OpenJDK versions also load the library.
  • ffmpeg, optionally, if you'll use MinimStreamer to convert formats.
FreeBSD 13 has no packages anymore. FreeBSD 13 reached end of life, and its package repositories are gone, so pkg install fails on 13.x. TrueNAS CORE is based on FreeBSD 13, so its jails are 13.x too. A jail that already has Java can be used as it is. For a new jail, Java has to come from somewhere else, such as building it from the ports tree. On FreeBSD 14 and later, packages install normally.

A jail for MinimServer

A jail of its own keeps MinimServer apart from the rest of the system. On TrueNAS CORE, create one in the web UI or with iocage. Give it its own network stack (VNET), so that UPnP's multicast discovery reaches it. For example:

iocage create -n minim -r release vnet=1 dhcp=1 bpf=1 boot=1
iocage fstab -a minim /mnt/pool/music /media nullfs ro 0 0

Here release is a FreeBSD release your system offers, such as 13.1-RELEASE; see the note above about packages on 13.x. The second line makes your music folder visible in the jail as /media, read-only. Change /mnt/pool/music to where your music is. The commands in the rest of this page are run inside the jail, as root: iocage console minim.

Installing

  1. Install Java (and ffmpeg, if you want it):

    pkg install openjdk8-jre ffmpeg

    Unlike earlier FreeBSD builds of ohNet, these don't need lang/gcc, and fetch replaces wget.

  2. Create a user to run MinimServer, rather than running it as root:

    pw useradd minimserver -c MinimServer -d /nonexistent -s /usr/sbin/nologin

    It needs to be able to read your music folder. A read-only mount that everyone can read is enough.

  3. Download MinimServer from its Downloads page: the Linux build for Intel, MinimServer-2.2-linux-intel.tar.gz. The download asks you to accept MinimServer's license terms. Copy the file into the jail, for example into /tmp, and unpack it:

    tar xzf /tmp/MinimServer-2.2-linux-intel.tar.gz -C /usr/local/share
chown -R minimserver:minimserver /usr/local/share/minimserver

    MinimServer keeps its settings and its updates in this folder, so the user running it has to own it.

  4. Install the service script:

    fetch -o /usr/local/etc/rc.d/minimserver \
    https://raw.githubusercontent.com/imush/ohnet-freebsd/main/rc.d/minimserver
chmod 555 /usr/local/etc/rc.d/minimserver
sysrc minimserver_enable=YES minimserver_user=minimserver

    MinimServer's own bin/stopall and bin/startd look for a running server in /proc or with Linux ps options, neither of which works on FreeBSD. This script starts MinimServer with startd, which also restarts it after an update, but finds and stops it by itself.

  5. Start it once, to let it update:

    service minimserver start

    On its first start, MinimServer updates itself to the latest version. The update brings the Linux ohNet, so after about half a minute it stops with this error in /usr/local/share/minimserver/data/minimserver.log:

    java.lang.UnsatisfiedLinkError: ... Shared object "libm.so.6" not found

    That's expected. The next step replaces it.

  6. Replace ohNet with the FreeBSD build. See which version MinimServer wants:

    service minimserver stop
ls /usr/local/share/minimserver/libext/ohnet*

    Download the zip with that name from the releases page, saving it under MinimServer's name. For ohnet(linux-intel)-1.37.5521.2.zip:

    cd /usr/local/share/minimserver/libext
fetch -o 'ohnet(linux-intel)-1.37.5521.2.zip' \
    https://github.com/imush/ohnet-freebsd/releases/download/v1.37.5521.2/ohnet.linux-intel.-1.37.5521.2.zip
chown minimserver:minimserver 'ohnet(linux-intel)-1.37.5521.2.zip'
sha256 'ohnet(linux-intel)-1.37.5521.2.zip'

    GitHub doesn't allow parentheses in download names, so the release lists the file with dots instead. Compare the checksum with the .sha256 file on the release page.

  7. Start MinimServer:

    service minimserver start
service minimserver status

    MinimServer unpacks ohNet into tmp/native/ as it starts. The log ends with "Startup complete".

  8. Set it up in a browser at http://jail-address:9790. Accept the license terms, then choose your music folder: /media with the mount above. MinimServer scans it, and then appears in any UPnP control point on your network.

After MinimServer updates

MinimServer updates itself, and most updates leave ohNet alone: an update that keeps the same ohNet version keeps your FreeBSD zip. For example, going from update 272 to 275 kept it.

When an update moves to a new ohNet version, MinimServer downloads that version's Linux zip and fails with the libm.so.6 error above. A FreeBSD zip under the new name will be on the releases page. Install it as in step 6. If you'd rather choose when to update, turn off automatic updates in MinimServer's settings.

Moving an existing install to these builds

If you followed the earlier tutorial in the MinimServer forum:

  1. Replace /etc/rc.d/minimserver with the new script, so stopping works without patching stopall after each update:

    service minimserver stop
pgrep -f mserver.jar && echo "still running: stop it first"
rm /etc/rc.d/minimserver
fetch -o /usr/local/etc/rc.d/minimserver \
    https://raw.githubusercontent.com/imush/ohnet-freebsd/main/rc.d/minimserver
chmod 555 /usr/local/etc/rc.d/minimserver

    If the old stop didn't stop it (the pgrep line prints a number), MinimServer's update replaced the patched stopall. Stop it with kill on that number, then carry on. The new script runs MinimServer as root, as before, unless you set minimserver_user.

  2. Keep a copy of your current zip, then replace it as in step 6:

    mkdir -p /root/ohnet-backup
cp -p /usr/local/share/minimserver/libext/ohnet*.zip /root/ohnet-backup/

  3. Start MinimServer with service minimserver start.

The new zips don't use lang/gcc. You can remove it if nothing else in the jail needs it.

Troubleshooting

Shared object "libm.so.6" not found

MinimServer is using a Linux ohNet. This happens after an update brings a new one, or if the FreeBSD zip was saved under the wrong name. Check that the name in libext/ is exactly MinimServer's, then see step 6.

Unable to create symbolic link /tmp/.minimserver/...

MinimServer was run earlier as a different user, such as root. Stop it, remove /tmp/.minimserver and start it again.

The server doesn't show up in control points

Check that it's running with service minimserver status, and look at the end of data/minimserver.log. Discovery uses multicast, so a jail needs VNET, and the jail and your control points must be on the same network.

Something else

Ask in the FreeBSD thread of the MinimServer forum, or open an issue on GitHub.
